Algorithms · Time Complexity

How Fast is Activity Selection?

Why the Earliest-Finish-Time (EFT) greedy strategy is so fast: break the work into two simple steps, count the checks, and see why it beats testing every combination.

⏱️ 1. Context · Why Speed Matters

Imagine choosing the most non-overlapping activities for a day. How many steps does the computer need as the list of n activities grows?

  • The Slow Way (Brute Force · O(2ⁿ)): Tests every possible mix of activities. For just 30 activities, that's over 1 billion checks!
  • The Fast Way (Greedy EFT · O(n log n)): Sort by finish time once, then walk through the list a single time. For 30 activities, it takes only ~180 steps.
The Complexity Rule: Total Time = Sorting + One Quick Pass.

Sorting takes O(n log n) and the loop takes O(n), giving O(n log n) overall. And if the list is already sorted, it takes just O(n)!

🧭 3. Evidence & Proof · Why O(n log n)?

We can prove the time complexity by counting the work in the two parts of the code:

Step 1 · Sorting the list O(n log n) Putting n activities in order of finish time takes about n × log₂(n) comparisons. (Skip this if already sorted!)
Step 2 · Scanning the list once O(n) The for loop checks each activity only once (start >= last_finish). It never goes backward or re-checks earlier activities, so n items = n checks.
Step 3 · Add them together O(n log n) Total O(n log n) + O(n) = O(n log n) because in Big-O we keep the biggest term that grows fastest.
Example with numbers: For 1,000 activities, Sorting ≈ 10,000 steps + Scanning = 1,000 checks → Only 11,000 total steps!
