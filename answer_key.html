Item 1 • 4 Pics 1 Word ANSWER: GREEDY

Clues: 1. Immediate ₱20 coin grab; 2. Short-sighted lens on "NOW"; 3. One-way highway (no backtracking); 4. `prioritize(c)` + `solution.append()`. Word length: 6 letters.

Rationale: A Greedy Algorithm always commits permanently to the most advantageous choice right now (local optimum) without exploring all futures or backtracking.

Item 2 • 4 Pics 1 Word ANSWER: BRUTE FORCE

Clues: 1. Endless key ring trying every key; 2. Exponential 2ⁿ curve; 3. Overheated 100% CPU burn; 4. Full permutation search tree. Word length: 10 letters (2 words).

Rationale: Brute Force exhaustively tests all 2ⁿ subsets or n! permutations, which becomes computationally impossible as input size n scales higher.

Correct Pill: The Red Pill (Permanent Commitment: No Undo, No Backtracking).
Rationale: Slide 1 line 99 explicitly documents: # Permanent commitment: no undo / backtracking. Greedy never backtracks; candidates are never on probation.

Item 4 • Coin Change Dilemma ANSWER: THE RED PILL

Question: Why does the Greedy strategy guarantee the minimum coins in the {₱20, ₱10, ₱5, ₱1} sandbox?

Correct Pill: The Red Pill (Divisibility Principle).
Rationale: ₱20, ₱10, ₱5, and ₱1 divide neatly into each other. Replacing one ₱20 requires two ₱10s, and replacing one ₱5 requires five ₱1s. The Blue Pill claim that greedy always works for any arbitrary coins (like {4, 3, 1}) is false as noted in Slide 1!

"This greedy algorithm strategy maximizes the total number of non-overlapping activities scheduled by always prioritizing tasks that finish soonest."

Rationale: The Earliest-Finish-Time (EFT) heuristic picks activities with the minimal finish time, leaving the largest remaining time available for subsequent events.

Rationale: Sorting activities by ascending finish times (requiring $O(n \log n)$) is the mandatory prerequisite before the linear greedy scan can take place.

Quiz 3: Why Earliest Finish Works

2 Items
Question 1 • Algorithm Implementation CORE CONCEPT: Greedy Compatibility Filter

How does the Earliest Finish algorithm select the maximum number of non-overlapping activities in a program?

1. Sort: Sort all $n$ activities in ascending order of finish time ($f_1 \le f_2 \le \dots \le f_n$).

2. Initialize: Select the first activity $A_1$ (which finishes earliest of all).

3. Scan: For each subsequent activity $i$, check if its start time $s_i \ge f_{last}$ (finish time of last chosen activity). If compatible, append activity $i$ and update $f_{last} = f_i$.

Question 2 • Correctness & Efficiency COMPLEXITY: O(n log n)

Why does sorting activities by their finish time help guarantee an optimal solution, and what is the algorithm's time complexity?

Why It Guarantees Optimality: By finishing as early as possible, the first chosen activity frees up the maximum possible remaining time window for future activities. Through the Exchange Argument, any optimal schedule that doesn't start with the earliest-finishing activity can replace its first item with the greedy choice without causing conflicts, proving the greedy choice is never worse than any alternative.

Time Complexity: $O(n \log n)$ for sorting the activities, plus $O(n)$ for the single linear scan. Total overall time is dominated by sorting: $O(n \log n)$.

Quiz 4: When Greedy Algorithms Fail

2 Items
Question 1 • Local vs Global Optimum CORRECT OPTION: B

Question: Why do greedy algorithms sometimes fail to find the optimal solution?

Correct Answer: B) They make locally optimal choices that permanently lock them out of the global optimum.

Rationale: Greedy algorithms decide strictly based on immediate, local gain. When a problem lacks the greedy-choice property, a short-sighted local choice permanently closes the door to a superior overall combination.

Question 2 • The 0/1 Knapsack Problem CORRECT OPTION: C

Question: In the 0/1 Knapsack problem, why does the greedy approach (sorting by best value-to-weight ratio) fail?

Correct Answer: C) It maximizes short-term ratio, potentially leaving empty space that a better combination of lower-ratio items could efficiently fill.

Rationale: Because items cannot be divided (0 or 1), greedily grabbing the item with the highest density can leave unused weight capacity that cannot fit remaining large items, whereas Dynamic Programming explores all subsets to achieve the optimal payload.
