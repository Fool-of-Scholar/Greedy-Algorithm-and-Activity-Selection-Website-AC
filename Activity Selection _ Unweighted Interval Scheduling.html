Activity Selection / Unweighted Interval Scheduling

Algorithm Complexity

Context

Several activities want one shared room. Each has a start and a finish time, and two activities cannot overlap. Touching at one moment is fine: one ending at 6 and another starting at 6 are compatible.

Goal: select the maximum number of mutually compatible activities.

Unweighted

Every activity has equal value, so we maximize the count, not total profit or weight.

Greedy idea

Take the best-looking choice now and never reconsider it.

Which choice?

The activity that finishes earliest frees the room soonest, leaving the most time for later activities.

Method: Earliest-Finish-Time-First

  1. Sort all activities by increasing finish time.
  2. Select the activity that finishes earliest.
  3. Examine the remaining activities in sorted order.
  4. Select one only if its start ≥ the finish of the last selected activity.
  5. Continue until every activity has been examined.
ActivitySelection(activities):
  sort activities by increasing finish time
  selected = []
  last_finish = -infinity

  for activity in activities:
    if activity.start >= last_finish:
      selected.append(activity)
      last_finish = activity.finish

  return selected
In plain terms: last_finish is the moment the room becomes free. Each activity is tested once against it: starts in time, take it and update last_finish; otherwise skip it. The algorithm never backtracks, and the sorting happens once, before any selection.

Evidence / Proof of correctness

Simple version: if a best schedule starts with some other activity X, swap X for the earliest-finishing activity G. G ends no later, so nothing breaks and the schedule is just as big. Picking G first never hurts.

Greedy-choice property: a locally best first choice can always be extended to an optimal solution. Exchange argument:

  1. Take an optimal schedule whose first activity is X.
  2. Let G be the activity with the earliest finish time.
  3. If X ≠ G, replace X with G.
  4. Since f(G) ≤ f(X), every other activity (which starts at or after f(X)) is still compatible with G.
  5. The swap keeps the same number of activities, so the schedule is still optimal.
  6. Repeat on the remaining activities that start at or after f(G).

Conclusion: earliest-finish-time-first returns a maximum-size compatible schedule.

Summary and references

Problem

Choose the most mutually compatible activities for one resource.

Strategy

Sort by finish time; take each activity that starts at or after the last finish.

Correctness

Exchange argument: the earliest finisher can replace any optimal first choice.
